# 需求文档：自定义标题栏

## 概述
用自定义的应用程序工具栏替换原生窗口标题栏，该工具栏集成了窗口控制（关闭按钮）和应用程序操作（添加、网格、设置），同时保持基本的窗口管理功能（拖动、关闭）。

## 用户故事

### US-1: 自定义标题栏显示
**作为** 用户
**我想要** 看到自定义标题栏而不是原生的 macOS 窗口控制按钮
**以便** 应用程序具有现代化、集成的外观，并有更多的垂直空间

**验收标准：**
- 隐藏原生窗口装饰（红绿灯按钮）
- 在窗口顶部显示自定义工具栏
- 工具栏左侧包含一个红色关闭按钮
- 关闭按钮旁边包含操作按钮（加号、网格、设置）
- 工具栏右侧包含一个用于切换侧边栏的箭头按钮
- 工具栏具有一致的高度和样式，与设计稿匹配

**EARS 表示法：**
- **当** 应用程序窗口显示时
- **系统应** 在顶部显示自定义标题栏
- **并且** 原生窗口装饰**应**被隐藏

### US-2: 关闭窗口功能
**作为** 用户
**我想要** 点击红色按钮来关闭应用程序窗口
**以便** 我可以使用自定义控件退出应用程序

**验收标准：**
- 点击红色关闭按钮会关闭应用程序窗口
- 关闭按钮具有悬停状态以提供视觉反馈
- 关闭按钮位于工具栏左侧
- 按钮为圆形且为红色

**EARS 表示法：**
- **当** 用户点击红色关闭按钮时
- **应用程序窗口应** 关闭
- **其中** 关闭按钮位于自定义标题栏中

### US-3: 窗口拖动
**作为** 用户
**我想要** 通过点击并拖动自定义标题栏的任意位置来拖动窗口
**以便** 我可以在屏幕上重新定位窗口

**验收标准：**
- 整个自定义标题栏区域充当拖动手柄
- 在标题栏的任何空白区域都可以拖动
- 交互元素（按钮）在点击时不会触发拖动
- 拖动行为与原生窗口拖动行为一致

**EARS 表示法：**
- **当** 用户在自定义标题栏上点击并拖动时
- **窗口应** 跟随光标移动
- **除非** 点击的是交互按钮

### US-4: 工具栏按钮功能
**作为** 用户
**我想要** 工具栏按钮（加号、网格、设置、箭头）保持功能正常
**以便** 我可以从自定义标题栏访问应用程序功能

**验收标准：**
- 加号按钮添加新的待办事项
- 网格按钮保持其当前功能
- 设置按钮切换语言（当前行为）
- 箭头按钮切换侧边栏可见性
- 所有按钮都有悬停状态
- 按钮在点击时不会触发窗口拖动

**EARS 表示法：**
- **当** 用户点击工具栏按钮时
- **相应的操作应** 执行
- **并且** 窗口拖动**不应**被触发

## 功能需求

### FR-1: 窗口配置
- 应用程序**应**禁用原生窗口装饰
- 窗口**应**保持其当前的大小约束（最小：400x500，默认：600x700）
- 窗口**应**保持可调整大小

### FR-2: 自定义标题栏组件
- 自定义标题栏**应**位于窗口顶部
- 标题栏**应**具有固定高度
- 标题栏**应**包含关闭按钮、操作按钮和侧边栏切换按钮
- 标题栏**应**使用现有的设计系统（Tailwind CSS、Radix UI）

### FR-3: 窗口控制
- 关闭按钮**应**调用 Tauri 窗口关闭 API
- 标题栏**应**通过 Tauri 拖动 API 支持窗口拖动
- 交互元素**应**在点击时阻止拖动行为

### FR-4: 视觉设计
- 关闭按钮**应**为圆形、红色，直径为 12px（3 个单位）
- 关闭按钮**应**具有降低不透明度的悬停状态
- 标题栏**应**具有与当前设计匹配的底部边框
- 标题栏**应**与现有 UI 保持一致的间距

## 非功能需求

### NFR-1: 性能
- 窗口拖动**应**流畅且响应迅速
- 按钮交互**应**没有可察觉的延迟

### NFR-2: 跨平台兼容性
- 实现**应**在 macOS 上工作（基于截图的主要目标）
- 实现**应该**在 Windows 和 Linux 上工作
- 平台特定的样式差异**应**得到妥善处理

### NFR-3: 可维护性
- 自定义标题栏**应**作为可重用组件实现
- 实现**应**遵循现有的代码模式和约定
- 代码**应**使用 TypeScript 以确保类型安全

### NFR-4: 可访问性
- 关闭按钮**应**具有适当的 aria-label
- 所有交互元素**应**可通过键盘访问
- 焦点状态**应**可见

## 技术约束

### TC-1: 技术栈
- **必须**使用 Tauri v2.8.5 API
- **必须**使用 React 19.1.0 和 TypeScript
- **必须**使用现有的 UI 组件库（Radix UI + Tailwind CSS）
- **必须**使用 Lucide React 图标

### TC-2: Tauri API
- **必须**使用 `getCurrentWindow().close()` 关闭窗口
- **必须**使用 `getCurrentWindow().startDragging()` 拖动窗口
- **必须**使用 `data-tauri-drag-region` 属性标记拖动区域
- **必须**在 capabilities 配置中添加所需权限

### TC-3: 现有代码
- **必须**修改 `src-tauri/tauri.conf.json` 以禁用装饰
- **必须**更新 `src-tauri/capabilities/default.json` 添加窗口权限
- **必须**修改 `src/components/todo-window.tsx` 实现自定义标题栏
- **应该**在复杂度需要时将标题栏提取为单独的组件

## 依赖项

### 外部依赖
- `@tauri-apps/api`（已安装）- 用于窗口管理 API

### 内部依赖
- `src/components/ui/button.tsx` - 用于工具栏按钮
- `src/index.css` - 用于样式
- 来自 `lucide-react` 的现有图标导入

## 范围外

以下内容明确**不**包含在此规范中：

- 最小化和最大化窗口控制（仅需要关闭按钮）
- 自定义窗口调整大小手柄
- 窗口透明度或模糊效果
- 动画窗口过渡
- 多窗口支持
- 标题栏的自定义上下文菜单
- 与 Tauri v1 的向后兼容性

## 成功指标

- 自定义标题栏在视觉上与提供的设计稿完全一致
- 所有窗口管理功能（关闭、拖动）正常工作
- 现有功能（待办事项管理、侧边栏等）没有退化
- 代码通过 TypeScript 编译且无错误
- 应用程序在 macOS 上成功构建和运行

## 假设

- 用户运行的是 macOS（基于显示 macOS 样式窗口的截图）
- 除装饰外，现有窗口配置是可接受的
- 红色关闭按钮是唯一需要的窗口控制（无最小化/最大化）
- 应保留当前工具栏按钮功能
- 应用程序仅用于桌面使用（非移动端）
