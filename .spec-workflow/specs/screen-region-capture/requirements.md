# 交互式屏幕区域截图功能需求规范

## 概述

### 功能描述
为ImageTodo应用添加交互式**屏幕级别**区域截图功能。用户按下快捷键后,应用创建一个独立的全屏覆盖层窗口(覆盖整个屏幕,包括所有其他应用程序),用户通过鼠标拖拽选择要截取的矩形区域,释放鼠标后立即截取**屏幕上**选中区域的内容并保存。该功能基于xcap库的`capture_region`API实现,提供类似Windows Snipping Tool或macOS截图工具的直观体验。

**重要说明**:
- 截图的是**屏幕内容**,不是应用窗口内容
- 覆盖层窗口是独立于主Todo窗口的全屏窗口
- 用户可以选择屏幕上的任意区域,包括:
  - 其他应用程序(浏览器、IDE、文件管理器等)
  - 桌面背景
  - 系统通知
  - 主Todo应用本身
  - 任何可见的屏幕内容

### 业务价值
- **直观易用**: 可视化选择,无需配置坐标,降低使用门槛
- **精准捕获**: 实时预览选择区域,确保截取准确内容
- **高效工作流**: 即选即截,无需后期裁剪,提升工作效率
- **专业体验**: 与主流截图工具一致的交互模式,用户无需学习
- **灵活应用**: 每次可选择不同区域,适应各种截图场景

### 目标用户
- 所有需要截取屏幕特定区域的ImageTodo用户
- UI/UX设计师需要截取界面元素
- 测试人员需要记录bug现场
- 内容创作者需要截取特定内容
- 文档编写者需要截取操作步骤

### 用户故事

**场景1: UI设计师截取浏览器元素**
> "作为一名UI设计师,我经常需要截取Chrome浏览器中的特定UI元素。我的Todo应用只占屏幕一小部分,但当我按下快捷键后,会出现一个覆盖整个屏幕的选择层。我可以拖拽选择Chrome中的按钮、表单或任何元素,立即得到精确的截图。这比切换到其他截图工具方便太多了!"

**场景2: 开发者截取IDE代码**
> "我在VS Code中写代码,Todo应用在旁边。当我需要截取某段代码分享给同事时,直接在Todo应用中按快捷键,选择VS Code中的代码区域,瞬间完成。不需要打开其他截图工具,也不需要裁剪全屏截图。"

**场景3: 测试人员记录Bug**
> "测试应用时发现Bug,我需要截取错误提示框。Todo应用虽然很小,但它的区域截图功能可以让我选择屏幕上任何位置的内容,包括其他应用的错误弹窗。这让Bug记录变得非常高效。"

## 功能需求

### FR-001: 快捷键触发全屏覆盖层
**作为** ImageTodo用户
**我想要** 按下快捷键后立即进入屏幕级别的区域选择模式
**以便** 快速开始截取屏幕上任意区域的内容

**验收标准**:
- **当** 用户按下区域截图快捷键(默认Alt+Shift+P)时
- **那么** 应用应创建一个独立的全屏覆盖层窗口
- **并且** 覆盖层应覆盖整个主显示器(不仅仅是Todo应用窗口)
- **并且** 覆盖层应在所有窗口之上,包括其他应用程序
- **并且** 覆盖层应在100ms内显示
- **并且** 鼠标光标应变为十字准星样式
- **并且** 用户可以看到屏幕上所有内容(通过半透明遮罩)

**技术说明**:
- 覆盖层是一个独立的Tauri窗口,与主Todo窗口(350x450)分离
- 覆盖层窗口配置:fullscreen=true, transparent=true, alwaysOnTop=true
- 覆盖层可以覆盖桌面、浏览器、IDE等所有可见应用

**EARS标准**:
- **Event**: 用户按下区域截图快捷键
- **Action**: 创建并显示全屏覆盖层窗口
- **Response**: 覆盖层显示,等待用户选择屏幕上的任意区域
- **State**: 应用可在前台或后台运行

### FR-002: 覆盖层视觉设计
**作为** ImageTodo用户  
**我想要** 清晰的视觉反馈显示选择状态  
**以便** 准确地选择目标区域

**验收标准**:
- **当** 覆盖层显示时
- **那么** 整个屏幕应覆盖半透明黑色遮罩(透明度60%)
- **并且** 鼠标光标应为十字准星(crosshair)
- **并且** 覆盖层应完全透明,不影响屏幕内容可见性
- **并且** 覆盖层应在所有窗口之上(topmost)

**EARS标准**:
- **Event**: 覆盖层窗口创建完成
- **Action**: 渲染半透明遮罩和准星光标
- **Response**: 用户看到选择界面
- **State**: 覆盖层已显示

### FR-003: 鼠标拖拽选择区域
**作为** ImageTodo用户  
**我想要** 通过拖拽鼠标绘制选择矩形  
**以便** 直观地选择要截取的区域

**验收标准**:
- **当** 用户在覆盖层上按下鼠标左键并拖拽时
- **那么** 应绘制一个矩形选择框
- **并且** 选择框应从按下位置开始,跟随鼠标移动
- **并且** 选择框内部应完全透明,显示原始屏幕内容
- **并且** 选择框外部应保持半透明遮罩
- **并且** 选择框应有明显的边框(蓝色或白色,2-3像素宽)
- **并且** 拖拽过程应流畅,无明显延迟(60fps)

**EARS标准**:
- **Event**: 用户按下鼠标左键并移动
- **Action**: 实时计算并绘制选择矩形
- **Response**: 选择框跟随鼠标移动
- **State**: 鼠标左键按下状态

### FR-004: 实时显示选择信息
**作为** ImageTodo用户  
**我想要** 实时看到选择区域的尺寸和坐标  
**以便** 精确控制选择范围

**验收标准**:
- **当** 用户正在拖拽选择时
- **那么** 应在选择框附近显示当前尺寸(如"800 × 600")
- **并且** 信息应实时更新,跟随鼠标移动
- **并且** 信息应清晰可读,与背景有足够对比度
- **并且** 信息位置应避免遮挡选择框
- **并且** 信息应包含宽度和高度(像素单位)

**EARS标准**:
- **Event**: 选择框尺寸变化
- **Action**: 更新尺寸显示文本
- **Response**: 用户看到实时尺寸信息
- **State**: 正在拖拽选择

### FR-005: 完成选择并截取屏幕内容
**作为** ImageTodo用户
**我想要** 释放鼠标后立即获得屏幕上选中区域的截图
**以便** 快速完成截图任务

**验收标准**:
- **当** 用户释放鼠标左键时
- **那么** 系统应立即捕获**屏幕上**选中矩形区域的内容
- **并且** 截图内容应为屏幕显示的实际内容,不是覆盖层窗口的内容
- **并且** 截图应保存为PNG格式
- **并且** 文件名应为`screenshot_region_{timestamp}.png`格式
- **并且** 截图应保存到用户的下载文件夹
- **并且** 覆盖层窗口应立即关闭
- **并且** 应显示"区域截图已保存"的toast通知

**技术说明**:
- 使用xcap的`capture_region(x, y, width, height)`捕获屏幕内容
- 坐标是相对于屏幕的,不是相对于覆盖层窗口的
- 截图发生在覆盖层关闭之前,确保捕获的是原始屏幕内容

**示例**:
- 用户选择了Chrome浏览器中的一个按钮(坐标:x=500, y=300, 宽=200, 高=50)
- xcap截取屏幕坐标(500, 300)处200x50像素的内容
- 截图内容是Chrome按钮的实际显示,不包含覆盖层的遮罩

**EARS标准**:
- **Event**: 用户释放鼠标左键
- **Action**: 调用xcap捕获屏幕上选中区域并保存
- **Response**: 截图保存,覆盖层关闭,显示通知
- **State**: 选择已完成

### FR-006: 最小选择区域限制
**作为** ImageTodo用户  
**我想要** 系统防止选择过小的区域  
**以便** 避免无意义的截图

**验收标准**:
- **当** 用户选择的区域小于最小尺寸(50x50像素)时
- **那么** 系统应显示toast提示"选择区域过小,请重新选择"
- **并且** 不应执行截图操作
- **并且** 覆盖层应保持显示,允许重新选择
- **并且** 最小尺寸应为50x50像素

**EARS标准**:
- **Event**: 用户释放鼠标但区域过小
- **Action**: 显示错误提示
- **Response**: 不截图,保持覆盖层
- **State**: 选择无效

### FR-007: 取消选择操作
**作为** ImageTodo用户  
**我想要** 能够取消区域选择  
**以便** 在不想截图时退出选择模式

**验收标准**:
- **当** 覆盖层显示时
- **那么** 用户按下Esc键应关闭覆盖层
- **并且** 用户右键点击应关闭覆盖层
- **并且** 关闭覆盖层不应触发截图
- **并且** 应用应返回正常状态
- **并且** 不应显示任何通知

**EARS标准**:
- **Event**: 用户按下Esc或右键点击
- **Action**: 关闭覆盖层窗口
- **Response**: 返回正常状态,不截图
- **State**: 覆盖层已显示

### FR-008: 独立快捷键配置
**作为** ImageTodo用户  
**我想要** 为区域截图配置独立的快捷键  
**以便** 区分全屏截图和区域截图操作

**验收标准**:
- **当** 用户在设置中配置区域截图快捷键时
- **那么** 系统应验证快捷键与全屏截图快捷键不冲突
- **并且** 默认快捷键应为Alt+Shift+P
- **并且** 系统应注册新的全局快捷键
- **并且** 快捷键配置应持久化保存
- **并且** 冲突的快捷键应被拒绝并显示错误提示

**EARS标准**:
- **Event**: 用户保存区域截图快捷键
- **Action**: 验证无冲突并注册快捷键
- **Response**: 快捷键生效或显示冲突错误
- **State**: 用户在设置界面

### FR-009: 成功反馈
**作为** ImageTodo用户  
**我想要** 在截图成功后收到明确的反馈  
**以便** 知道区域截图已成功保存

**验收标准**:
- **当** 区域截图成功保存后
- **那么** 系统应显示toast通知"区域截图已保存"
- **并且** 通知应在3秒后自动消失
- **并且** 通知应支持国际化(中文/英文)

**EARS标准**:
- **Event**: 区域截图文件成功保存
- **Action**: 显示toast通知
- **Response**: 用户看到成功消息
- **State**: 无特定状态要求

### FR-010: 错误处理与反馈
**作为** ImageTodo用户  
**我想要** 在截图失败时收到清晰的错误信息  
**以便** 了解失败原因并采取相应措施

**验收标准**:
- **当** 区域截图操作失败时(如权限不足、磁盘空间不足等)
- **那么** 系统应显示toast通知"区域截图失败"
- **并且** 通知应包含具体的失败原因
- **并且** 通知应支持国际化
- **并且** 错误信息应记录到控制台日志

**EARS标准**:
- **Event**: 区域截图操作遇到错误
- **Action**: 显示错误toast并记录日志
- **Response**: 用户了解失败情况
- **State**: 无特定状态要求

## 非功能需求

### NFR-001: 性能要求
- 覆盖层应在快捷键触发后100ms内显示
- 选择框绘制应流畅,保持60fps
- 区域截图应在选择完成后0.5秒内完成
- 覆盖层关闭应立即响应,无延迟
- 内存使用应保持在合理范围(覆盖层增量不超过50MB)

### NFR-002: 可靠性要求
- 区域截图成功率应达到99%以上(在正常系统条件下)
- 覆盖层应正确处理多显示器场景(初期仅支持主显示器)
- 系统应优雅处理所有可能的错误情况
- 不应因区域截图失败导致应用崩溃
- 覆盖层应正确处理窗口焦点和层级

### NFR-003: 可用性要求
- 覆盖层UI应直观易懂,无需说明即可使用
- 选择框应清晰可见,与背景有明显对比
- 尺寸显示应实时更新,易于阅读
- 取消操作应明显且易于触发(Esc键、右键)
- 错误提示应清晰说明问题和解决方法

### NFR-004: 兼容性要求
- 必须与现有全屏截图功能共存,互不干扰
- 必须兼容现有的设置管理系统
- 必须兼容现有的快捷键系统
- 应支持Windows、macOS和Linux(X11)
- 应正确处理不同DPI设置和缩放比例

### NFR-005: 可维护性要求
- 代码应遵循项目现有的架构模式
- 应添加适当的注释说明复杂逻辑
- 覆盖层组件应独立可测试
- 应更新相关文档(README、CHANGELOG等)
- 应包含单元测试覆盖核心功能

## 约束条件

### 技术约束
- 必须使用Tauri 2.x创建覆盖层窗口
- 必须使用Rust语言实现后端区域截图功能
- 必须使用xcap库的`capture_region` API
- 必须通过Tauri命令与前端通信
- 覆盖层必须使用React + TypeScript实现
- 必须保持与现有截图系统的一致性

### 设计约束
- 覆盖层UI应简洁,不应有复杂的控件
- 选择框样式应与主流截图工具一致
- Toast通知样式应与现有通知一致
- 快捷键配置应遵循现有模式
- 不应破坏现有的全屏截图功能

### 业务约束
- 初始版本仅支持主显示器区域截图
- 多显示器支持可作为未来增强
- 必须提供清晰的取消机制,降低误操作风险
- 覆盖层应尽可能轻量,避免影响系统性能

### 平台约束
- Linux Wayland支持有限,应提供清晰的错误提示
- macOS可能需要用户授予屏幕录制权限(与全屏截图相同)
- Windows需要8.1或更高版本
- 不同DPI设置下坐标计算可能需要调整
- 覆盖层窗口在不同平台上的行为可能有差异

### 测试场景1: 基本屏幕区域选择和截图
**前置条件**: ImageTodo应用(350x450)在屏幕左上角运行,Chrome浏览器在屏幕中央打开

1. 在Todo应用中按下区域截图快捷键(默认Alt+Shift+P)
2. **验证**: 应显示覆盖整个屏幕的覆盖层(不仅仅是Todo应用区域)
3. **验证**: 可以看到Todo应用、Chrome浏览器、桌面等所有内容(通过半透明遮罩)
4. **验证**: 鼠标变为十字准星
5. 在Chrome浏览器的地址栏上拖拽选择一个矩形区域(如600x40)
6. **验证**: 选择框应实时跟随鼠标,显示尺寸信息
7. **验证**: 选择框内部透明,可以清楚看到Chrome地址栏
8. 释放鼠标
9. **验证**: 覆盖层应立即关闭
10. **验证**: 应显示"区域截图已保存"的toast通知
11. **验证**: 下载文件夹中应出现新的PNG截图文件
12. **验证**: 文件名应包含"region"和时间戳
13. **验证**: 打开截图文件,应显示Chrome地址栏的内容(不是Todo应用的内容)
14. **验证**: 截图中不应包含覆盖层的遮罩或选择框

## 依赖关系

### 外部依赖
- **xcap** (Rust crate): 核心屏幕捕获库,提供`capture_region` API
- **image** (Rust crate): 图像处理和格式转换
- **tauri** (Rust crate): Tauri框架核心,用于创建覆盖层窗口
- **@tauri-apps/api** (npm): Tauri前端API
- **React** (npm): 覆盖层UI框架
- **TypeScript** (npm): 类型安全

### 内部依赖
- 全局快捷键系统 (src/lib/shortcuts.ts) - 必须扩展以支持第二个快捷键
- 设置管理系统 (src/lib/settings.ts) - 必须扩展以支持区域截图快捷键配置
- Toast通知系统 (sonner) - 用于用户反馈
- 现有截图系统 (src/lib/screenshot.ts) - 必须扩展以支持区域截图

### 系统依赖
- **Linux**: libxcb, libxrandr, dbus, pipewire, wayland, mesa
- **macOS**: 屏幕录制权限
- **Windows**: Windows 8.1或更高版本

## 风险与缓解

### 风险1: 覆盖层窗口在不同平台上行为不一致
- **影响**: 用户体验在不同平台上差异较大
- **概率**: 中
- **缓解**: 在所有支持的平台上进行充分测试,针对平台差异进行适配

### 风险2: 覆盖层性能问题导致选择框延迟
- **影响**: 用户体验差,选择不精确
- **概率**: 中
- **缓解**: 优化渲染逻辑,使用硬件加速,避免不必要的重绘

### 风险3: 不同DPI设置下坐标计算不准确
- **影响**: 截图区域与选择不符
- **概率**: 中(特别是Windows高DPI)
- **缓解**: 实现DPI感知的坐标计算,在多种DPI设置下测试

### 风险4: 覆盖层窗口焦点和层级问题
- **影响**: 覆盖层无法正确显示或接收输入
- **概率**: 低
- **缓解**: 正确配置Tauri窗口属性(always_on_top, skip_taskbar等)

### 风险5: 用户误操作导致频繁取消
- **影响**: 用户体验受影响
- **概率**: 低
- **缓解**: 提供清晰的取消机制(Esc、右键),并在UI上给予提示

## 未来增强

以下功能不在当前范围内,但可作为未来增强考虑:

1. **多显示器支持**: 允许用户在多个显示器上选择区域
2. **选择框调整**: 选择完成后可以调整选择框的大小和位置
3. **预设区域快捷选择**: 提供常用尺寸的快速选择按钮
4. **选择历史**: 记录最近使用的选择区域,快速重用
5. **固定比例选择**: 支持按固定比例(如16:9)选择区域
6. **选择框样式自定义**: 允许用户自定义选择框颜色和样式
7. **截图后编辑**: 选择完成后进入简单的编辑模式(标注、裁剪等)
8. **OCR集成**: 对选中区域进行文字识别
9. **延迟截图**: 选择区域后延迟几秒再截图
10. **滚动截图**: 支持截取超出屏幕的长内容
