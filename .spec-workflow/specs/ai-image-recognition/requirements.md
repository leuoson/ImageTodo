# AI图像识别待办事项 - 需求规格说明 (v2.0)

## 📋 版本更新说明

**v2.0 (2025-01-03) - OCR与AI分离架构**:
- ✅ **架构改进**: OCR和AI功能完全分离
- ✅ **本地OCR**: 使用leptess(Tesseract)进行本地文本识别
- ✅ **AI可选**: AI仅用于内容总结和智能分析(可选功能)
- ✅ **隐私优先**: OCR完全本地处理,无需上传图像到云端
- ✅ **成本优化**: 基础OCR免费,AI总结按需使用

**v1.0 (初始版本)**:
- 完全依赖AI进行图像识别和文本提取

## 概述

本规格说明定义了为ImageTodo应用添加图像识别功能的需求。用户将能够将截图(已通过现有截图功能复制到剪贴板)粘贴到待办事项中,系统通过**本地OCR**识别文本内容,可选使用**AI**进行智能总结,并在点击待办事项时查看原始图片。

## 业务背景

### 问题陈述
目前,ImageTodo用户可以将截图捕获到剪贴板,但无法:
1. 将这些截图附加到待办事项
2. 自动从截图中提取有意义的信息
3. 将视觉信息转换为可操作的文本待办事项
4. 稍后引用原始截图

### 解决方案愿景
将ImageTodo转变为智能视觉任务管理器,用户可以:
- 直接将截图粘贴到待办事项输入框
- 让AI自动分析和总结图像内容
- 从视觉信息创建基于文本的待办事项
- 通过点击图像待办事项查看原始图片

### 成功标准
- 用户可以从剪贴板粘贴图像到待办事项输入框
- AI成功提取和总结图像内容,准确率>90%
- 从图像创建待办事项耗时<5秒
- 图像查看即时且直观
- 功能支持离线模式并优雅降级

## 功能需求

### FR-001: 图像粘贴检测
**作为** ImageTodo用户
**我想要** 将剪贴板中的图像粘贴到待办事项输入框
**以便** 快速从截图创建待办事项

**验收标准:**
- **当** 用户在待办事项输入框中粘贴(Ctrl/Cmd+V)
- **并且** 剪贴板包含图像
- **那么** 应用检测到图像粘贴事件
- **并且** 显示加载指示器
- **并且** 阻止正常的文本粘贴行为

**EARS格式:**
- **事件(Event)**: 用户在待办事项输入框按下Ctrl/Cmd+V
- **行动(Action)**: 检查剪贴板是否有图像数据
- **响应(Response)**: 如果检测到图像则触发图像处理工作流
- **状态(State)**: 待办事项输入框已聚焦

**技术说明:**
- 使用浏览器的`paste`事件监听器
- 检查`event.clipboardData.items`中的图像类型
- 支持常见格式: PNG、JPEG、WebP
- 文件大小限制: 10MB

---

### FR-002: 图像存储
**作为** ImageTodo用户
**我想要** 粘贴的图像保存到本地
**以便** 即使离线也能稍后查看

**验收标准:**
- **当** 粘贴图像时
- **那么** 图像保存到本地存储
- **并且** 生成唯一标识符
- **并且** 文件路径与待办事项一起存储
- **并且** 图像存储在专用文件夹中
- **并且** 删除待办事项时清理旧图像

**EARS格式:**
- **事件(Event)**: 检测到图像粘贴
- **行动(Action)**: 将图像保存到本地文件系统
- **响应(Response)**: 返回文件路径和唯一ID
- **状态(State)**: 剪贴板中有可用的图像数据

**技术说明:**
- 保存路径: `{app_data}/images/{todo_id}_{timestamp}.png`
- 使用Tauri的文件系统API
- 为todo_id生成UUID
- 实现待办事项删除时的清理功能

---

### FR-003: 本地OCR文本识别 (核心功能)
**作为** ImageTodo用户
**我想要** 系统自动识别粘贴图像中的文本
**以便** 快速从截图创建待办事项,无需手动输入

**验收标准:**
- **当** 图像被粘贴并保存后
- **那么** 使用本地OCR引擎(Tesseract)识别文本
- **并且** 提取的文本显示为待办事项内容
- **并且** 处理在3秒内完成
- **并且** 完全离线工作,无需网络
- **并且** 支持中英文识别
- **并且** 错误被优雅处理(如无文本则提示用户手动输入)

**EARS格式:**
- **事件(Event)**: 图像成功保存
- **行动(Action)**: 使用Tesseract OCR识别图像中的文本
- **响应(Response)**: 提取的文本填充到待办事项输入框
- **状态(State)**: 图像文件已存在于本地

**技术说明:**
- OCR引擎: leptess (Tesseract Rust绑定)
- 支持语言: 中文(chi_sim) + 英文(eng)
- 图像预处理: 自动二值化、去噪
- 超时: 5秒
- 完全本地处理,保护隐私
- 重试逻辑: 2次尝试
- 错误处理: AI失败时允许手动输入文本

---

### FR-004: AI智能总结 (可选增强功能)
**作为** 高级用户
**我想要** 在OCR识别后可选使用AI进行智能总结
**以便** 获得更简洁、更有意义的待办事项描述

**验收标准:**
- **当** OCR成功提取文本后
- **并且** 用户启用了AI总结功能
- **那么** 将OCR文本发送给AI进行总结
- **并且** AI生成简洁的1-2句话摘要
- **并且** 用户可以选择使用原始OCR文本或AI摘要
- **并且** AI处理失败时自动回退到OCR文本
- **并且** 默认模式可在设置中配置

**EARS格式:**
- **事件(Event)**: OCR文本提取完成
- **行动(Action)**: 如果启用AI,将文本发送给AI总结
- **响应(Response)**: 显示AI摘要或OCR原文
- **状态(State)**: OCR已完成,AI功能已启用

**技术说明:**
- 设置: `useAISummary: boolean` (默认false)
- AI提供商: OpenAI GPT-4 / OpenRouter / 其他
- 输入: OCR提取的文本
- 输出: 简洁摘要
- 超时: 5秒
- 成本: 按使用付费(可选功能)

---

### FR-005: 待办事项数据模型扩展
**作为** 开发者
**我想要** 待办事项数据模型支持图像附件
**以便** 正确存储和检索基于图像的待办事项

**验收标准:**
- **当** 从图像创建待办事项时
- **那么** 待办事项包含图像元数据
- **并且** 保留原始文本
- **并且** 存储图像路径
- **并且** 记录处理方法
- **并且** 所有数据在应用重启后持久化

**EARS格式:**
- **事件(Event)**: 使用图像创建待办事项
- **行动(Action)**: 使用图像字段扩展待办事项对象
- **响应(Response)**: 将扩展的待办事项保存到存储
- **状态(State)**: 图像已处理并保存

**技术说明:**
```typescript
interface Todo {
  id: string
  text: string  // 显示的文本(OCR原文或AI摘要)
  completed: boolean
  createdAt: number
  // 新增字段:
  hasImage?: boolean
  imagePath?: string
  imageProcessingMethod?: 'ocr' | 'ocr+ai'  // ocr=仅OCR, ocr+ai=OCR+AI总结
  originalOcrText?: string  // OCR提取的原始文本
  aiSummary?: string  // AI生成的摘要(如果使用)
}
```

### FR-006: 图像查看弹窗
**作为** ImageTodo用户
**我想要** 点击基于图像的待办事项以查看原始图片
**以便** 看到任务的视觉上下文

**验收标准:**
- **当** 用户点击带有图像的待办事项时
- **那么** 弹窗/模态框显示原始图像
- **并且** 图像以全分辨率显示
- **并且** 弹窗可以通过ESC键或点击外部关闭
- **并且** 弹窗同时显示图像和提取的文本
- **并且** 弹窗响应式并在所有屏幕尺寸上工作

**EARS格式:**
- **事件(Event)**: 用户点击基于图像的待办事项
- **行动(Action)**: 在模态框中加载并显示图像
- **响应(Response)**: 显示图像及其元数据
- **状态(State)**: 待办事项有关联的图像

**技术说明:**
- 使用现有的Radix UI Dialog组件
- 从本地路径加载图像
- 显示: 图像、提取的文本、处理方法
- 支持大图像的缩放/平移
- 延迟加载图像以提高性能

---

### FR-007: 视觉指示器
**作为** ImageTodo用户
**我想要** 看到哪些待办事项附加了图像
**以便** 快速识别基于图像的任务

**验收标准:**
- **当** 查看待办事项列表时
- **那么** 带有图像的待办事项显示视觉指示器(图标)
- **并且** 指示器清晰可见
- **并且** 指示器与应用设计一致
- **并且** 悬停时显示预览工具提示(可选)

**EARS格式:**
- **事件(Event)**: 待办事项列表渲染
- **行动(Action)**: 检查每个待办事项是否有图像附件
- **响应(Response)**: 为基于图像的待办事项显示图像图标
- **状态(State)**: 待办事项列表已显示

**技术说明:**
- 使用lucide-react图标: `Image`或`FileImage`
- 位置: 待办事项文本旁边
- 颜色: 强调色
- 工具提示: 悬停时显示缩略图(未来增强)

## 非功能需求

### NFR-001: 性能
- 图像粘贴检测: <100ms
- 图像保存到磁盘: <500ms
- **OCR处理: <3秒** (本地处理,无网络延迟)
- AI总结(可选): <5秒
- 图像弹窗加载: <200ms
- 处理期间应用保持响应

### NFR-002: 可靠性
- **OCR完全离线**: 100%可用性,无网络依赖
- AI总结失败时自动回退到OCR文本
- 优雅降级: 允许手动文本输入
- 处理失败时无数据丢失
- Tesseract引擎稳定可靠

### NFR-003: 安全性与隐私
- **OCR完全本地处理**: 图像永不上传到云端
- API密钥安全存储(仅AI总结功能需要)
- AI总结是可选功能,默认关闭
- 用户完全控制数据是否发送到AI
- 不记录敏感数据
- 安全的API通信(HTTPS,仅AI功能)

### NFR-004: 可用性
- 处理期间清晰的加载状态
- 信息丰富的错误消息
- AI生成文本的撤销功能
- 始终可用的手动文本编辑
- 与现有UI/UX模式一致

### NFR-005: 国际化
- 所有UI文本支持中文和英文
- 错误消息本地化
- **OCR支持中英文**: chi_sim + eng语言包
- AI摘要使用用户首选语言(可选功能)

### NFR-006: 可扩展性
- 支持多达1000个基于图像的待办事项
- 高效的图像存储(压缩)
- 清理孤立图像
- 图像密集型列表的分页

## 用户故事摘要

1. **快速图像待办事项创建**: 粘贴截图 → 本地OCR识别 → 创建待办事项
2. **智能总结(可选)**: OCR文本 → AI总结 → 更简洁的待办
3. **视觉参考**: 点击待办事项 → 查看原始图像
4. **完全离线**: 核心OCR功能无需网络,完全本地处理
5. **数据隐私**: 图像永不上传,AI总结是可选功能

## 验收测试

### 测试场景1: 基础OCR流程(默认)
1. 用户截图(Alt+Shift+P)
2. 用户聚焦待办事项输入框并粘贴(Ctrl+V)
3. 出现加载指示器"正在识别文本..."
4. 3秒内,本地OCR提取文本
5. OCR文本填充到输入框
6. 用户可以编辑或直接创建待办
7. 待办事项显示图像指示器图标
8. 用户点击待办事项,图像弹窗出现
9. 用户可以看到原始截图和OCR文本

### 测试场景2: AI增强流程(可选)
1. 用户在设置中启用"AI智能总结"
2. 用户粘贴图像
3. 本地OCR先提取文本(3秒)
4. OCR文本发送给AI进行总结(5秒)
5. AI返回简洁摘要
6. 用户可以选择使用OCR原文或AI摘要
7. 创建待办事项

### 测试场景3: 完全离线模式
1. 用户断开互联网连接
2. 用户粘贴图像

4. 使用OCR文本创建待办事项

1. 用户粘贴图像
2. OCR识别失败或无文本

5. 图像仍然保存并关联到待办

## 术语表

- **OCR**: 光学字符识别 - 从图像中提取文本的技术
- **Tesseract**: 开源OCR引擎,由Google维护
- **leptess**: Tesseract的Rust绑定库
- **AI总结**: 使用AI模型对OCR文本进行智能总结(可选功能)
- **基于图像的待办事项**: 从粘贴的图像创建的带有OCR文本的待办事项
- **语言包**: Tesseract的语言数据文件(如chi_sim, eng)
