# 屏幕区域截图功能修复 - 需求规范

## 概述

### 功能描述
修复现有屏幕区域截图功能的三个关键问题,并增强用户体验:
1. **坐标位置偏差** - 选择框位置与实际截图区域不匹配
2. **只能截取桌面** - 截图只显示桌面背景,无法截取其他应用窗口内容
3. **剪贴板支持** - 自动将截图复制到系统剪贴板

### 问题分析

#### 问题1: 坐标位置偏差(严重)
**现象**: 用户在覆盖层上选择的矩形区域与最终截图的实际区域不匹配,特别是在高DPI显示器(如Retina、4K)上偏差明显。

**根本原因**:
- 前端使用`e.clientX`和`e.clientY`获取鼠标坐标,这些是CSS像素
- 在高DPI显示器上,1个CSS像素 = 2个或更多物理像素
- xcap的`capture_region`期望物理屏幕坐标
- 当前实现没有进行缩放因子转换

**影响**: 用户无法准确截取想要的区域,功能基本不可用

#### 问题2: 只能截取桌面(严重)
**现象**: 截图只显示桌面背景,即使用户选择了浏览器、IDE等应用窗口的内容,截图中也看不到这些内容。

**根本原因**:
- 查看`src-tauri/src/lib.rs`第211-213行:先调用`monitor.capture_region()`截图
- 查看第230-232行:然后才关闭覆盖层窗口
- 截图时覆盖层窗口仍然可见,其半透明遮罩遮挡了下方内容
- xcap捕获的是包含覆盖层的屏幕内容

**影响**: 功能完全失效,无法截取任何有用内容

#### 问题3: 缺少剪贴板功能(增强)
**现象**: 截图只保存到文件,用户需要手动打开文件才能使用。

**用户需求**: 截图后直接粘贴到其他应用(如聊天软件、文档编辑器)是常见工作流。

**影响**: 用户体验不佳,需要额外步骤

### 业务价值
- **修复关键缺陷**: 使功能真正可用,避免用户流失
- **提升准确性**: 确保截图区域与选择一致,提高工作效率
- **优化工作流**: 剪贴板支持减少操作步骤,提升用户满意度
- **跨平台一致性**: 在所有DPI设置下都能正常工作

### 目标用户
- 所有使用ImageTodo屏幕区域截图功能的用户
- 特别是使用高DPI显示器(Retina、4K)的用户
- 需要快速分享截图的用户

## 功能需求

### FR-001: DPI缩放因子处理
**作为** ImageTodo用户
**我想要** 选择框位置与实际截图区域完全匹配
**以便** 准确截取我想要的内容

**验收标准**:
- **当** 用户在任何DPI设置的显示器上使用区域截图时
- **那么** 选择框的位置应与最终截图的区域完全一致
- **并且** 在标准DPI(1.0x)显示器上正常工作
- **并且** 在高DPI(2.0x、3.0x)显示器上正常工作
- **并且** 坐标转换应在前端完成,后端接收物理像素坐标
- **并且** 缩放因子应在覆盖层窗口创建时获取

**技术说明**:
- 使用Tauri的`window.scaleFactor()`API获取缩放因子
- 在前端将CSS像素坐标乘以缩放因子转换为物理像素
- 示例:Retina显示器(2.0x),CSS坐标(100, 100)转换为物理坐标(200, 200)

**EARS标准**:
- **Event**: 用户释放鼠标完成选择
- **Action**: 将CSS像素坐标乘以缩放因子
- **Response**: 发送物理像素坐标给Rust后端
- **State**: 缩放因子已获取并存储

### FR-002: 截图前隐藏覆盖层窗口
**作为** ImageTodo用户
**我想要** 截图能够捕获其他应用窗口的实际内容
**以便** 截取浏览器、IDE等应用中的信息

**验收标准**:
- **当** 用户选择包含其他应用窗口的区域时
- **那么** 截图应显示该应用窗口的实际内容
- **并且** 截图中不应包含覆盖层的半透明遮罩
- **并且** 截图中不应包含选择框边框
- **并且** 覆盖层应在截图前完全隐藏
- **并且** 隐藏后应有足够延迟确保窗口已隐藏(50-100ms)
- **并且** 截图完成后应关闭覆盖层窗口

**技术说明**:
- 修改`capture_screen_region`函数执行顺序:
  1. 获取覆盖层窗口引用
  2. 调用`window.hide()`隐藏窗口
  3. 使用`std::thread::sleep(Duration::from_millis(100))`等待
  4. 调用`monitor.capture_region()`截图
  5. 关闭窗口

**EARS标准**:
- **Event**: Rust接收到截图命令
- **Action**: 隐藏窗口,等待,然后截图
- **Response**: 返回不包含覆盖层的截图
- **State**: 覆盖层窗口存在

### FR-003: 自动复制到剪贴板
**作为** ImageTodo用户
**我想要** 截图自动复制到剪贴板
**以便** 直接粘贴到其他应用中使用

**验收标准**:
- **当** 区域截图成功完成时
- **那么** 图片应自动复制到系统剪贴板
- **并且** 图片仍应保存到下载文件夹(保持现有功能)
- **并且** 成功提示应说明"截图已保存并复制到剪贴板"
- **并且** 剪贴板复制失败不应影响文件保存
- **并且** 剪贴板复制失败应显示警告提示
- **并且** 支持Windows、macOS和Linux平台

**技术说明**:
- 使用`arboard` crate(版本3.x)进行剪贴板操作
- 在保存文件后复制到剪贴板
- 剪贴板操作使用try-catch包裹,失败不影响主流程

**EARS标准**:
- **Event**: 截图文件保存成功
- **Action**: 将图片复制到剪贴板
- **Response**: 显示包含剪贴板状态的成功消息
- **State**: 截图已保存

### FR-004: 改进的用户反馈
**作为** ImageTodo用户
**我想要** 清晰的反馈信息
**以便** 了解截图和剪贴板操作的状态

**验收标准**:
- **当** 截图和剪贴板复制都成功时
- **那么** 应显示"截图已保存并复制到剪贴板"
- **当** 截图成功但剪贴板复制失败时
- **那么** 应显示"截图已保存,但复制到剪贴板失败"
- **并且** 所有消息应支持国际化(中文/英文)
- **并且** 消息应在3秒后自动消失

**EARS标准**:
- **Event**: 截图操作完成
- **Action**: 根据操作结果显示相应消息
- **Response**: 用户了解操作状态
- **State**: 无特定状态要求

## 非功能需求

### NFR-001: 性能要求
- 缩放因子获取应在100ms内完成
- 窗口隐藏延迟应为50-100ms(可配置)
- 剪贴板复制应在100ms内完成
- 总体截图时间增加不超过200ms
- 不应影响选择框拖拽的流畅度(60fps)

### NFR-002: 可靠性要求
- 坐标转换准确率100%(在支持的DPI范围内)
- 截图内容准确率100%(不包含覆盖层)
- 剪贴板复制成功率>95%(在正常系统条件下)
- 剪贴板失败不应导致截图失败
- 所有平台行为一致

### NFR-003: 兼容性要求
- 支持DPI缩放因子:1.0x、1.25x、1.5x、2.0x、3.0x
- 支持Windows 8.1+、macOS 10.13+、Linux(X11)
- 与现有截图功能完全兼容
- 不破坏现有的快捷键和设置系统

### NFR-004: 可维护性要求
- 代码修改应最小化,避免大规模重构
- 添加适当的注释说明修复原因
- 更新相关文档(README、CHANGELOG)
- 保持与现有代码风格一致

## 约束条件

### 技术约束
- 必须使用Tauri 2.x的window API
- 必须使用arboard 3.x进行剪贴板操作
- 必须保持与xcap 0.7的兼容性
- 不能修改Tauri命令的签名(保持向后兼容)

### 设计约束
- 不应改变用户界面外观
- 不应改变现有的交互流程
- 窗口隐藏应对用户不可见或影响最小
- 剪贴板功能应是附加的,不影响文件保存

### 业务约束
- 必须修复问题1和问题2(关键缺陷)
- 问题3(剪贴板)是增强功能,可选但推荐
- 修复应在一个版本中完成
- 不应引入新的已知问题

## 验收测试

### 测试场景1: DPI缩放准确性
**前置条件**: 
- 标准DPI显示器(1.0x)
- 高DPI显示器(2.0x Retina)

1. 在标准DPI显示器上打开应用
2. 按下区域截图快捷键
3. 选择一个200x200像素的区域
4. **验证**: 截图文件尺寸应为200x200像素
5. **验证**: 截图内容应与选择框位置完全匹配
6. 切换到高DPI显示器
7. 重复步骤2-5
8. **验证**: 在2.0x显示器上,选择100x100 CSS像素应生成200x200物理像素截图
9. **验证**: 截图内容应与选择框位置完全匹配

### 测试场景2: 截取应用窗口内容
**前置条件**:

1. 按下区域截图快捷键
2. 选择Chrome浏览器地址栏区域
3. 释放鼠标完成截图
4. **验证**: 截图应显示Chrome地址栏的实际内容
5. **验证**: 截图中不应有半透明遮罩
6. **验证**: 截图中不应有选择框边框
7. 再次按下快捷键
8. 选择VS Code代码编辑器区域
9. **验证**: 截图应显示代码内容
10. 选择跨越Todo应用和桌面的区域
11. **验证**: 截图应同时包含Todo应用和桌面内容

### 测试场景3: 剪贴板功能
1. 按下区域截图快捷键
2. 选择一个区域并完成截图

## 风险与缓解

### 风险1: 窗口隐藏延迟不足
- **影响**: 截图仍可能包含覆盖层
- **概率**: 中
- **缓解**: 在多个平台上测试不同延迟值,选择最优值;如需要可使平台特定

### 风险2: arboard在某些平台上不稳定
- **影响**: 剪贴板功能失效
- **概率**: 低
- **缓解**: 使用try-catch包裹,失败不影响文件保存;arboard是成熟库,风险较低

### 风险3: 缩放因子在多显示器环境下不准确
- **影响**: 多显示器用户坐标仍不准确
- **概率**: 低
- **缓解**: 当前仅支持主显示器(已文档化);未来可扩展支持

### 风险4: 性能影响
- **影响**: 截图操作变慢
- **概率**: 低
- **缓解**: 添加的延迟和操作都很小(<200ms);在实际设备上测试性能

## 未来增强

以下功能不在当前范围内,但可作为未来增强考虑:

1. **可配置延迟**: 允许用户在设置中调整窗口隐藏延迟
2. **剪贴板优先模式**: 选项只复制到剪贴板,不保存文件
3. **多显示器支持**: 正确处理不同显示器的不同缩放因子
4. **动态缩放因子**: 监听缩放因子变化事件
5. **剪贴板历史**: 保存最近的截图到剪贴板历史
