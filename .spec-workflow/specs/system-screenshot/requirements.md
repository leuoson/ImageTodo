# 系统截图功能需求规范

## 概述

### 功能描述
将ImageTodo应用的截图功能从基于DOM的html2canvas实现迁移到基于原生屏幕捕获的xcap库实现。用户通过全局快捷键触发截图时,系统将捕获整个屏幕(主显示器)而非仅应用窗口的DOM内容,并将截图保存到用户的下载文件夹。

### 业务价值
- **更高质量的截图**: 原生屏幕捕获可以捕获完整的屏幕内容,包括非DOM元素(如系统通知、其他应用窗口等)
- **更好的性能**: 原生实现比DOM渲染方式更快,响应更迅速
- **跨平台一致性**: xcap提供统一的跨平台API,确保在Windows、macOS和Linux上的一致体验
- **更小的包体积**: 移除html2canvas后减少前端依赖,降低应用体积

### 目标用户
所有ImageTodo应用的用户,特别是需要快速截图功能的用户。

## 功能需求

### FR-001: 原生屏幕截图
**作为** ImageTodo用户  
**我想要** 通过快捷键触发原生屏幕截图  
**以便** 快速捕获当前屏幕内容

**验收标准**:
- **当** 用户按下配置的全局快捷键(默认Alt+P)时
- **那么** 系统应捕获主显示器的完整屏幕内容
- **并且** 截图应保存为PNG格式文件
- **并且** 文件名应包含时间戳(格式: `screenshot-{timestamp}.png`)
- **并且** 截图应保存到用户的下载文件夹

**EARS标准**:
- **Event**: 用户按下全局快捷键
- **Action**: 系统捕获主显示器屏幕
- **Response**: 保存PNG格式截图到下载文件夹
- **State**: 应用可以在前台或后台运行

### FR-002: 截图成功反馈
**作为** ImageTodo用户  
**我想要** 在截图成功后收到明确的反馈  
**以便** 知道截图已成功保存

**验收标准**:
- **当** 截图成功保存后
- **那么** 系统应显示成功提示消息
- **并且** 消息应包含"截图已保存"的文本
- **并且** 消息应使用toast通知形式显示
- **并且** 消息应在3秒后自动消失

**EARS标准**:
- **Event**: 截图文件成功保存
- **Action**: 显示toast通知
- **Response**: 用户看到成功消息
- **State**: 无特定状态要求

### FR-003: 截图失败处理
**作为** ImageTodo用户  
**我想要** 在截图失败时收到错误提示  
**以便** 了解失败原因并采取相应措施

**验收标准**:
- **当** 截图操作失败时(如权限不足、磁盘空间不足等)
- **那么** 系统应显示错误提示消息
- **并且** 消息应包含"截图失败"的文本
- **并且** 消息应使用toast通知形式显示
- **并且** 错误信息应记录到控制台日志

**EARS标准**:
- **Event**: 截图操作遇到错误
- **Action**: 显示错误toast并记录日志
- **Response**: 用户了解失败情况
- **State**: 无特定状态要求

### FR-004: 保持现有快捷键配置
**作为** ImageTodo用户  
**我想要** 继续使用已配置的截图快捷键  
**以便** 无需重新学习新的操作方式

**验收标准**:
- **当** 用户已配置自定义快捷键时
- **那么** 新的截图功能应使用相同的快捷键
- **并且** 快捷键配置界面保持不变
- **并且** 快捷键设置应持久化保存

**EARS标准**:
- **Event**: 应用启动或快捷键配置更新
- **Action**: 注册用户配置的快捷键
- **Response**: 快捷键触发新的xcap截图功能
- **State**: 快捷键配置已保存在设置中

### FR-005: 跨平台支持
**作为** ImageTodo用户  
**我想要** 在不同操作系统上都能使用截图功能  
**以便** 在任何平台上都有一致的体验

**验收标准**:
- **当** 应用运行在Windows 8.1+、macOS或Linux(X11)上时
- **那么** 截图功能应正常工作
- **并且** 截图质量和性能应保持一致
- **并且** 文件保存路径应适配各平台的下载文件夹

**EARS标准**:
- **Event**: 用户在任何支持的平台上触发截图
- **Action**: 系统使用xcap捕获屏幕
- **Response**: 截图成功保存到平台对应的下载文件夹
- **State**: 应用运行在支持的操作系统上

## 非功能需求

### NFR-001: 性能要求
- 截图操作应在1秒内完成(从快捷键触发到文件保存)
- 截图不应导致应用界面卡顿或无响应
- 内存使用应保持在合理范围(截图过程中增量不超过50MB)

### NFR-002: 可靠性要求
- 截图成功率应达到99%以上(在正常系统条件下)
- 系统应优雅处理所有可能的错误情况
- 不应因截图失败导致应用崩溃

### NFR-003: 安全性要求
- 截图文件应保存到用户可控的位置(下载文件夹)
- 不应在未经用户同意的情况下上传或分享截图
- 应遵守各平台的屏幕捕获权限要求

### NFR-004: 可维护性要求
- 代码应遵循项目现有的架构模式
- 应提供清晰的错误日志便于调试
- 应移除所有html2canvas相关的废弃代码

### NFR-005: 兼容性要求
- 最低支持版本: Windows 8.1, macOS 10.13, Ubuntu 20.04
- 应在Tauri 2.x框架下正常工作
- 应与现有的全局快捷键插件兼容

## 约束条件

### 技术约束
- 必须使用Rust语言实现后端截图功能
- 必须使用xcap库进行屏幕捕获
- 必须通过Tauri命令与前端通信
- 必须保持现有的TypeScript接口不变(向后兼容)

### 设计约束
- 用户界面不应有任何变化
- 快捷键配置界面保持不变
- Toast通知样式与现有风格一致

### 业务约束
- 不能破坏现有的快捷键注册功能
- 必须在迁移完成后移除html2canvas依赖
- 初始版本仅支持主显示器截图(多显示器支持可作为未来增强)

### 平台约束
- Linux Wayland支持有限,应提供清晰的错误提示
- macOS可能需要用户授予屏幕录制权限
- Windows需要8.1或更高版本

## 验收测试

### 测试场景1: 基本截图功能
1. 启动ImageTodo应用
2. 按下配置的截图快捷键(默认Alt+P)
3. **验证**: 应显示"截图已保存"的成功提示
4. **验证**: 下载文件夹中应出现新的PNG截图文件
5. **验证**: 截图文件名应包含时间戳
6. **验证**: 打开截图文件,应显示完整的屏幕内容

### 测试场景2: 自定义快捷键
1. 打开设置弹窗
2. 将截图快捷键更改为Ctrl+Shift+S
3. 保存设置并关闭弹窗
4. 按下新配置的快捷键Ctrl+Shift+S
5. **验证**: 应成功触发截图
6. **验证**: 应显示成功提示
7. 重启应用
8. 按下Ctrl+Shift+S
9. **验证**: 快捷键配置应被保留,截图功能正常

### 测试场景3: 错误处理
1. 将下载文件夹设置为只读(模拟权限错误)
2. 按下截图快捷键
3. **验证**: 应显示"截图失败"的错误提示
4. **验证**: 控制台应记录详细的错误信息
5. **验证**: 应用应保持稳定,不应崩溃

### 测试场景4: 跨平台一致性
1. 在Windows、macOS和Linux(X11)上分别运行应用
2. 在每个平台上触发截图
3. **验证**: 所有平台上截图功能都应正常工作
4. **验证**: 截图应保存到各平台对应的下载文件夹
5. **验证**: 截图质量和性能应保持一致

### 测试场景5: 性能测试
1. 按下截图快捷键
2. **验证**: 从按下快捷键到显示成功提示应在1秒内完成
3. 连续快速按下快捷键5次
4. **验证**: 应生成5个截图文件
5. **验证**: 应用应保持响应,不应卡顿
6. **验证**: 内存使用应保持稳定

### 测试场景6: 迁移验证
1. 检查package.json
2. **验证**: html2canvas依赖应已移除
3. 检查src/lib/screenshot.ts
4. **验证**: 不应包含html2canvas的import语句
5. 检查应用包体积
6. **验证**: 相比迁移前应有所减小

## 依赖关系

### 外部依赖
- **xcap** (Rust crate): 核心屏幕捕获库
- **image** (Rust crate): 图像处理和格式转换
- **tauri** (Rust crate): Tauri框架核心
- **@tauri-apps/api** (npm): Tauri前端API

### 内部依赖
- 全局快捷键系统 (src/lib/shortcuts.ts)
- 设置管理系统 (src/lib/settings.ts)
- Toast通知系统 (sonner)

### 系统依赖
- **Linux**: libxcb, libxrandr, dbus, pipewire, wayland, mesa
- **macOS**: 屏幕录制权限
- **Windows**: Windows 8.1或更高版本

## 风险与缓解

### 风险1: xcap初始化失败
- **影响**: 用户无法使用截图功能
- **概率**: 低
- **缓解**: 实现详细的错误处理和用户友好的错误提示

### 风险2: 平台兼容性问题
- **影响**: 某些平台上功能不可用
- **概率**: 中(特别是Linux Wayland)
- **缓解**: 提前测试所有目标平台,为不支持的平台提供清晰说明

### 风险3: 权限问题
- **影响**: macOS用户可能需要手动授予权限
- **概率**: 高(首次使用)
- **缓解**: 提供清晰的权限请求说明和故障排除指南

### 风险4: 文件保存失败
- **影响**: 截图无法保存
- **概率**: 低
- **缓解**: 实现备用保存位置,提供详细的错误信息

### 风险5: 性能问题
- **影响**: 截图操作缓慢或导致应用卡顿
- **概率**: 低
- **缓解**: 在后台线程执行截图操作,实现适当的超时机制

## 未来增强

以下功能不在当前范围内,但可作为未来增强考虑:

1. **多显示器支持**: 允许用户选择要截图的显示器
2. **区域截图**: 允许用户选择屏幕的特定区域进行截图
3. **截图编辑**: 提供基本的截图编辑功能(裁剪、标注等)
4. **自动上传**: 将截图自动上传到云存储服务
5. **截图历史**: 在应用内查看和管理历史截图
6. **格式选择**: 支持JPEG、WebP等其他图像格式
7. **剪贴板支持**: 将截图直接复制到剪贴板
8. **延迟截图**: 设置延迟时间后再截图
